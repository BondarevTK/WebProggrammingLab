## Описание

Проект реализует простую страницу для публикации, просмотра,
редактирования и удаления твитов. Бэкенд написан на **FastAPI** и
отдаёт данные в формате JSON. Фронтенд — статические файлы
(`index.html`, `app.js`, `style.css`), которые обращаются к API через
`fetch`. Фреймворки на фронтенде не используются.

## Стек технологий

- **Python 3.11+**
- **FastAPI** — REST API
- **Pydantic** — валидация входных и выходных данных
- **Uvicorn** — ASGI-сервер
- **HTML + CSS + JavaScript (fetch)** — фронтенд
- **pytest + httpx** — тесты

## Модели данных

| Поле          | Тип   | Описание                           |
| ------------- | ----- | ---------------------------------- |
| `id`          | `int` | Уникальный идентификатор           |

### `tweetCreate` — входная модель для POST / PUT

| Поле          | Тип   | Описание  |
| ------------- | ----- | --------- |
| `title`       | `str` | Заголовок |

## API

Все эндпоинты отдают и принимают `application/json`.

| Метод    | URL           | Назначение                   | Коды ответа         |
| -------- | ------------- | ---------------------------- | ------------------- |
| `GET`    | `/tweet`      | Список всех твитов           | `200`               |
| `GET`    | `/tweet/{id}` | Один твит по id              | `200`, `400`        |
| `POST`   | `/tweet`      | Создать новый твит           | `201`, `422`        |
| `PUT`    | `/tweet/{id}` | Изменить title и description | `200`, `400`, `422` |
| `DELETE` | `/tweet/{id}` | Удалить твит                 | `200`, `400`        |

### Примеры запросов

**Получить список:**

```bash
curl http://localhost:8000/tweet
```

**Создать твит:**

```bash
curl -X POST http://localhost:8000/tweet \
  -H "Content-Type: application/json" \
  -d '{"title": "Привет", "description": "Первый пост"}'
```

**Изменить:**

```bash
curl -X PUT http://localhost:8000/tweet/1 \
  -H "Content-Type: application/json" \
  -d '{"title": "Обновлено", "description": "Новый текст"}'
```

**Удалить:**

```bash
curl -X DELETE http://localhost:8000/tweet/1
```

## Обработка ошибок

- **`400 Bad Request`** — id вне диапазона (например, `GET /tweet/999`).
- **`422 Unprocessable Entity`** — тело запроса не соответствует
  Pydantic-модели (пустой title, отсутствует description и т.п.).
- **`500`** — внутренние ошибки (не должны возникать при корректных данных).

FastAPI возвращает ошибки в формате `{"detail": "..."}`, и фронтенд
показывает это поле пользователю.

## Запуск

### 1. Установка зависимостей

```bash
pip install fastapi uvicorn[standard] pytest httpx
```

Или через `requirements.txt`:

```bash
pip install -r requirements.txt
```

### 2. Запуск бэкенда

```bash
uvicorn main:app --reload
```

Сервер поднимется на `http://localhost:8000`. Swagger UI доступен по
адресу `http://localhost:8000/docs`.

### 3. Запуск фронтенда

Откройте `index.html` в браузере. Если используете CORS — фронтенд
обращается к `http://localhost:8000/tweet`. Если отдаёте статику через
Nginx — используйте относительный путь `/api/tweet`.

## Пользовательский сценарий

1. **Просмотр списка.** При загрузке страницы `fetchTweets()` вызывает
   `GET /tweet` и рендерит карточки в `#tweets`.
2. **Создание.** Пользователь заполняет поля «Заголовок» и «Текст»,
   нажимает «Опубликовать». `POST /tweet` создаёт запись, после чего
   `fetchTweets()` перерисовывает список — новый пост появляется сверху.
3. **Просмотр деталей.** Клик по карточке вызывает `showDetails(note)` и
   показывает полный текст и кнопки «Редактировать» / «Удалить».
4. **Редактирование.** Кнопка «Редактировать» подставляет текущие
   значения в форму, кнопка «Опубликовать» меняется на «Сохранить».
   При отправке идёт `PUT /tweet/{id}`, затем `fetchTweets()`.
5. **Удаление.** Кнопка «Удалить» шлёт `DELETE /tweet/{id}` и
   перезагружает список — карточка исчезает.

Все действия происходят **без перезагрузки страницы**.

## Тесты

Покрыты:

- получение списка и одного твита;
- создание (успех и ошибка валидации);
- обновление (успех и несуществующий id);
- удаление (успех и несуществующий id).

### Что покрыто тестами

| Сценарий                   | Метод               | Проверяет                                    |
| -------------------------- | ------------------- | -------------------------------------------- |
| Список всех твитов         | `GET /tweet`        | Статус 200, список из 3 элементов, структура |
| Один твит                  | `GET /tweet/1`      | Статус 200, правильные поля                  |
| Несуществующий id          | `GET /tweet/999`    | Статус 400, есть `detail`                    |
| Создание                   | `POST /tweet`       | Статус 201, поля, рост списка                |
| Невалидное тело            | `POST /tweet`       | Статус 422                                   |
| Обновление                 | `PUT /tweet/0`      | Статус 200, новые title/description          |
| Обновление несуществующего | `PUT /tweet/999`    | Статус 400                                   |
| Пустое тело                | `PUT /tweet/0`      | Статус 422                                   |
| Удаление                   | `DELETE /tweet/0`   | Статус 200, список уменьшается               |
| Удаление несуществующего   | `DELETE /tweet/999` | Статус 400                                   |
| Изоляция состояния         | fixture             | Список восстанавливается                     |
