## Описание

Проект реализует страницу для публикации твитов и комментариев к ним.
В отличие от второй лабораторной работы, данные теперь хранятся не в оперативной памяти (Python-списке),
а в реляционной базе данных **PostgreSQL**. Это гарантирует, что после перезапуска сервера (или контейнера) все созданные записи сохранятся.

В качестве предметной области выбрана мини-социальная сеть:

- **Твит (`tweets`)** — аналог блокнота (главная сущность).
- **Комментарий (`comments`)** — аналог заметки (связанная сущность)

## Стек технологий

- **Python 3.11+**
- **FastAPI** — REST API
- **PostgreSQL 15** — реляционная база данных
- **SQLAlchemy** — ORM для работы с БД
- **Pydantic** — валидация данных
- **Docker / Docker Compose** — контейнеризация
- **HTML + CSS + JavaScript (fetch)** — фронтенд
- **pytest + httpx** — тесты

## Схема базы данных

Структура БД описана через модели SQLAlchemy.
Реализована связь **Один-ко-многим**: один Твит может содержать много Комментариев.

### Таблица `tweets` (Блокноты)

| Поле          | Тип                | Описание                 |
| ------------- | ------------------ | ------------------------ |
| `id`          | SERIAL PRIMARY KEY | Уникальный идентификатор |
| `title`       | VARCHAR            | Заголовок твита          |
| `description` | TEXT               | Текст твита              |
| `likes`       | INTEGER            | Лайки (по умолчанию 0)   |
| `created`     | TIMESTAMP          | Дата создания            |

### Таблица `comments` (Заметки)

| Поле          | Тип                | Описание                                        |
| ------------- | ------------------ | ----------------------------------------------- |
| `id`          | SERIAL PRIMARY KEY | Уникальный идентификатор                        |
| `post`        | INTEGER (FK)       | Внешний ключ на `tweets.id` (ON DELETE CASCADE) |
| `description` | TEXT               | Текст комментария                               |
| `likes`       | INTEGER            | Лайки (по умолчанию 0)                          |
| `created`     | TIMESTAMP          | Дата создания                                   |

## API

Все эндпоинты отдают и принимают `application/json`.

| Метод    | URL                              | Назначение                           | Коды ответа         |
| -------- | -------------------------------- | ------------------------------------ | ------------------- |
| `GET`    | `/tweet`                         | Список всех твитов                   | `200`               |
| `GET`    | `/tweet/{id}`                    | Один твит вместе с его комментариями | `200`, `404`        |
| `POST`   | `/tweet`                         | Создать новый твит                   | `201`, `422`        |
| `PUT`    | `/tweet/{id}`                    | Изменить title и description         | `200`, `404`, `422` |
| `DELETE` | `/tweet/{id}`                    | Удалить твит (и его комментарии)     | `204`, `404`        |
| `POST`   | `/tweet/{id}/comments`           | Добавить комментарий к твиту         | `201`, `404`, `422` |
| `DELETE` | `/tweet/{tweetId}/comments/{id}` | Удалить комментарий                  | `204`, `404`        |

### Примеры запросов

**Создать твит:**

```bash
curl -X POST http://localhost:8000/tweet \
  -H "Content-Type: application/json" \
  -d '{"title": "Учёба", "description": "Пост про учёбу"}'
```

**Добавить комментарий к твиту с id=1:**

```bash
curl -X POST http://localhost:8000/tweet/1/comments \
  -H "Content-Type: application/json" \
  -d '{"description": "Отличный пост!"}'
```

## Запуск проекта

### 1. Запуск через Docker Compose (Рекомендуемый)

Убедитесь, что у вас установлены Docker и Docker Compose.
Из корневой папки проекта выполните:

```bash
docker compose up --build
```

- **База данных** будет доступна внутри контейнеров (и проброшена на `localhost:5432`).
- **Бэкенд (FastAPI)** запустится на `http://localhost:8000`.
- **Фронтенд (Nginx)** откроется на `http://localhost:3000`.

> **Создание таблиц**: При первом запуске SQLAlchemy автоматически создаст таблицы на основе моделей (через `Base.metadata.create_all()`).

### 2. Локальный запуск (без Docker)

1. Установите PostgreSQL и создайте базу данных.
2. Пропишите строку подключения в переменную окружения `DATABASE_URL`:
   ```bash
   export DATABASE_URL="postgresql://user:password@localhost:5432/mydb"
   ```
3. Установите зависимости и запустите:
   ```bash
   cd backend
   pip install -r requirements.txt
   uvicorn main:app --reload
   ```

## Пользовательский сценарий

1. **Просмотр списка.** При загрузке страница делает `GET /tweet` и рендерит список.
2. **Создание.** Пользователь заполняет форму, нажимает «Опубликовать». `POST /tweet` сохраняет запись в PostgreSQL. Список перерисовывается.
3. **Просмотр деталей.** Клик по карточке вызывает `GET /tweet/{id}`. SQL-запрос через `JSON_AGG` собирает пост и все его комментарии в один ответ.
4. **Комментирование.** В деталях поста можно оставить комментарий. `POST /tweet/{id}/comments` сохраняет его в связанную таблицу.
5. **Удаление.** Удаление поста (каскадно удалит комментарии) или отдельного комментария.

## Тесты

Тесты используют `TestClient` и реальную тестовую базу данных (или SQLite в памяти, в зависимости от конфигурации фикстур).

Запуск:

```bash
cd backend
pytest test_main.py -v
```

Покрыты сценарии:

- `GET /tweet` — получение списка.
- `GET /tweet/{id}` — получение одного твита с вложенными комментариями.
- `POST /tweet` — успешное создание и ошибка валидации (422).
- `PUT /tweet/{id}` — успешное обновление.
- `DELETE /tweet/{id}` — удаление и проверка отсутствия (404).
- `POST /tweet/{id}/comments` — успешное добавление комментария к существующему твиту.
- `POST /tweet/999/comments` — ошибка 404 при попытке комментировать несуществующий твит.
